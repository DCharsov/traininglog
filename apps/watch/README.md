# TrainingLog Watch

## Нативное приложение iPhone

Новый основной путь — схема `TrainingLogiPhone`: полноценный SwiftUI-интерфейс
дневника и автоматическая связь с системно спаренными часами через WatchConnectivity.
Коды и ручные кнопки привязки на часах не нужны. Инструкция, текущие ограничения
и проверки: [iphone-native.md](../../docs/iphone-native.md).
Текущие изменения HealthKit, восстановления и редакторов, включая незавершённые
части плана: [native-health-progress.md](../../docs/native-health-progress.md).
Описанная ниже PWA-привязка — предыдущий совместимый серверный путь, не основной
интерфейс новой сборки часов.

## Текущий статус — 28 сентября 2026

Реализованы офлайн-ядро WorkoutCore, экраны тренировки, автоподстановка следующего
подхода, локальное сохранение и очередь, HTTPS-привязка и передача управления.
В API и PWA добавлен watch-протокол v1 поверх существующего контракта v2.
API и PWA опубликованы с разрешения владельца 28 сентября; функция часов включена.
Обновите PWA без очистки данных. В настройках Apple Watch нажмите «Подключить часы»,
на часах — «Подключить», затем на телефоне — «Это мои часы». Сверьте показанные слова;
набирать код, слова или пароль на часах не требуется.
Полный физический HTTPS-прогон ещё требует подтверждения. «Демо» на часах работает
отдельно и никогда не отправляется в личный дневник.

Следующий пустой подход получает только вес и повторы/секунды предыдущего
завершённого подхода того же упражнения, стороны и типа в текущей тренировке.
RIR, заметки, UUID и время не копируются. Подход подтверждается кнопкой «Готово».
При длинном названии экран прокручивается; Crown изменяет значение только внутри
открытого редактора поля. Если профиль оборудования не задаёт шаг или список весов,
редактор часов показывает выбор шага ввода 0,5 / 1 / 2,5 кг (изначально 0,5).
Кнопки ± и Crown используют этот шаг; настроенный профиль всегда имеет приоритет.
Также доступен прямой ввод через текстовое поле.

Инструкция по привязке, проверки и безопасная выкладка: [apple-watch-testing.md](../../docs/apple-watch-testing.md).
Ниже сохранён журнал этапа 0; его ранние ограничения не описывают текущий код.

## Исторический этап 0

Это проверка установки, а не готовый дневник. Проект создан штатным шаблоном
Xcode 26.0 → watchOS → App → Watch-only App. Контейнер iOS из шаблона не содержит
самостоятельного приложения iPhone. Сторонние зависимости и capabilities не добавлены.

Экран сохраняет счётчик атомарным JSON-файлом в Application Support, проверяет
`GET https://cleargate.ru/training/api/health` и планирует локальное уведомление
через 60 секунд. Серверные данные не изменяются. Перенаправления HTTPS запрещены;
cookie и авторизация не используются. Повреждённый файл блокирует изменение
счётчика и остаётся на диске. Ошибка записи не увеличивает отображаемое значение.

## Открытие и подпись

Откройте `apps/watch/TrainingLogWatch.xcodeproj` именно из этого репозитория.
Общая схема — `TrainingLogWatch`, исполняемый target — `TrainingLogWatch Watch App`.
В Xcode Settings → Accounts добавьте Apple Account. Пароль и 2FA вводит владелец.
Используется бесплатная Personal Team; покупка Developer Program не нужна.

Постоянные идентификаторы из шаблона:

- контейнер: `ru.dcharsov.TrainingLogWatch`;
- часы: `ru.dcharsov.TrainingLogWatch.watchkitapp`.

До первой установки проверьте их доступность для вашей Personal Team. После первой
установки сохраняйте те же идентификаторы и Team, иначе это может стать другим приложением.
Team ID запишите локально в `Config/Signing.local.xcconfig` по примеру
`Config/Signing.example.xcconfig`. Этот файл исключён из Git. Общий
`Signing.xcconfig` подключён к Debug и Release обоих targets. В Xcode проверьте
автоматическую подпись и выбранную Personal Team. Если Xcode записал Team ID прямо
в `project.pbxproj`, перенесите значение в локальный конфиг перед коммитом.

Минимальная версия пока watchOS 10.0 (используется Observation); это техническая
нижняя граница, а не установленная версия часов владельца. Уточнить по устройству.

## Проверка на физических часах

1. Подключите и разблокируйте iPhone, подтвердите доверие Mac. Часы должны быть
   спарены с ним и доступны Xcode. Включите Developer Mode, если Xcode потребует.
2. Запишите модель/размер часов и версии iOS/watchOS. Выберите физические часы
   в списке destination, затем Run. Сохраните точную ошибку, если подпись не прошла.
3. Нажмите «Сохранить +1» несколько раз, запишите значение. Остановите debugger
   и откройте приложение с часов. Проверьте значение после полного закрытия и запуска.
4. Нажмите «Проверить HTTPS»; нужен результат «HTTPS работает · API v2».
5. Разрешите уведомления, запланируйте проверку и откройте циферблат. Отдельно
   проверьте погашенный экран, Focus и отказ в разрешении. В открытом приложении
   системный баннер не запрашивается; основной сценарий этого теста — циферблат.
6. Ещё раз Run поверх установленного приложения. Не удаляйте его. Счётчик должен
   сохраниться. Только после этого этап 0 может считаться пройденным.

Срок бесплатного профиля — 7 дней с выдачи, согласно
[Apple](https://developer.apple.com/help/account/basics/about-your-developer-account/).
Фактическую дату смотрите в `ExpirationDate` подписанного `embedded.mobileprovision`
(например, `security cms -D -i /path/to/embedded.mobileprovision`, локально).
Не добавляйте профиль в Git: он содержит идентификаторы аккаунта и устройств.
Если дата недоступна, оценку по дате установки помечайте приблизительной.
Проверка после настоящего истечения срока остаётся отдельной отложенной проверкой.

## Команды

Запускать из корня репозитория:

```sh
bash scripts/watch-install.sh check
bash scripts/watch-install.sh simulator-build
bash scripts/watch-install.sh device-build ACTUAL_WATCH_DESTINATION_ID
bash scripts/watch-install.sh device-install ACTUAL_WATCH_DESTINATION_ID
```

Скрипт предпочитает `/Applications/Xcode-26.3.app`, если он установлен,
иначе использует `/Applications/Xcode.app`, даже если системный
`xcode-select` указывает на CommandLineTools; переопределение — через `DEVELOPER_DIR`.
`device-build` собирает и запрашивает автоматическую подпись, но не устанавливает
приложение. `device-install` дополнительно устанавливает и запускает через devicectl.
Этот путь проверен на Xcode 26.3 / Series 8 / watchOS 26.6; универсальная поддержка
других версий не заявлена. Установка также доступна через Run в Xcode.
Результаты сборки находятся в `~/Library/Developer/Xcode/DerivedData/TrainingLogWatch`
(переопределение: `WATCH_DERIVED_DATA`), вне синхронизируемой папки Documents.
Внутри Documents File Provider добавлял `com.apple.FinderInfo` к .app, что приводило
к ошибке CodeSign `resource fork, Finder information, or similar detritus not allowed`.

Для еженедельного обновления откройте этот же проект, выберите прежние Team и
bundle ID и выполните Run поверх приложения. Не удаляйте контейнер с данными.
После появления тренировок сначала отправляйте очередь на сервер; если подпись
уже истекла — восстанавливайте запуск повторной установкой, не сбросом данных.
