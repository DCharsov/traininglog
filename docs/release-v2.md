# Обновление учёта и справочников

Реализованный объём согласованного продолжения (14 сентября 2026): длительность, стороны, каталог оборудования, шаги веса, календарь отдыха, произвольные группы суперсетов, синхронизируемые архив/корзина и контракт API. Проверка на физическом телефоне исключена по просьбе владельца.

## Как пользоваться

- **Настройки → Оборудование:** создайте отдельный профиль для каждого тренажёра. Укажите известный шаг или список реальных делений через `;`. Список приоритетнее шага. Неизвестное можно оставить пустым.
- **Программа → Из каталога оборудования:** выберите профиль. Название, способ учёта и шаги копируются в шаблон; при начале занятия — в его неизменяемый снимок. Обновление каталога не меняет историю и уже выбранные настройки автоматически: для будущих тренировок выберите обновлённый профиль заново и сохраните программу.
- **Что записывать:** повторения или целые секунды (1–86400). **Стороны:** вместе или отдельно. При раздельном учёте для каждого запланированного подхода создаётся левая и правая строка. В графиках сторона выбирается отдельно. Длительность и повторы не смешиваются.
- **Группа суперсета:** одинаковая строка у двух или более упражнений. Пустое поле отключает группу. Навигатор чередует подходы участников; незавершённые строки можно заполнить в любом порядке. Старые взаимные пары Bro Split распознаются без миграции записей. Правки программы не меняют активное занятие.
- **Подставить прошлые значения:** заполняет только черновик соответствующего подхода; выполнение подтверждается отдельной кнопкой.
- **Настройки → Календарь отдыха:** выберите дату, запланируйте отдых и отметьте завершение. На главной виден отдых на сегодня; начало тренировки остаётся свободным.
- **Настройки → Архив и корзина:** архив скрывает из обычных списков, сохраняя статистику. Корзина исключает тренировку также из прогресса и подсказки следующего дня. Восстановление возвращает те же UUID и результаты. Активное занятие сначала нужно завершить или отменить. Окончательное физическое стирание не выполняется.

## Хранение и совместимость

IndexedDB v3 добавляет таблицы `equipment` и `calendar`, не переписывая существующие программы, черновики, метаданные и операции. Каталог оборудования — независимые документы с UUID; снимок упражнения содержит `equipmentId` и исторические настройки, без каскадного удаления. Сервер продолжает хранить ограниченные версионированные агрегаты в SQLite, с общей транзакцией snapshot/change/operation receipt. Отдельные SQL-таблицы для каждого поля снимка не нужны для выбранного протокола.

На всех четырёх типах документов действуют версии, неизменяемые повторные запросы, защита конфликтов и tombstones (`deletedAt`). `archivedAt` также синхронизируется. Редактирование и удаление с разных устройств дают явный конфликт с сохранением обеих версий. Восстановление JSON по-прежнему не удаляет серверные объекты неявно.

JSON v2 включает оба каталога и корзину. Читается и прежний JSON v1; импорт атомарно заменяет локальный набор, скачав его копию по существующему сценарию, и отключает синхронизацию до повторного подключения. CSV добавляет tracking, side, duration input/seconds, archived/deleted timestamps. Полная выгрузка включает корзину; графики исключают её.

API контракт: `apps/api/openapi.json`, доступен публично как описание схемы по `/training/api/openapi.json`; личных записей в схеме нет. TypeScript DTO генерируются из этого контракта и используются синхронизатором. Генератор OpenAPI из Zod: `node apps/web/scripts/build-contract.mjs`; генерация DTO: `npm --prefix tools/api-contract ci`, затем `npm --prefix tools/api-contract run generate`. Генератор изолирован с TypeScript 5, поскольку его peer requirement пока не включает TypeScript 6 основного приложения.

Запись требует `contractVersion:2`. Старый клиент получает 426 и сохраняет локальные данные. Обновление: закрыть все вкладки дневника и приложение с домашнего экрана, затем открыть снова. Service worker не прерывает активную тренировку. При выкладке сначала обновляется API, затем фронтенд.

`GET /{kind}/{id}` возвращает последний снимок и версию; `GET /{kind}?after=sequence` — страницы изменений выбранного каталога, включая tombstones. Полный bootstrap выполняется через поколение базы и общий `/changes`, как раньше. Единственный путь записи — идемпотентный `PUT /{kind}/{id}`. Разделение write-команд на create/update/delete не требуется: создание имеет baseVersion=0, удаление — новый снимок с deletedAt.

## Границы

Физический iPhone, поведение установленной PWA на реальном устройстве и реальные тренировки не проверялись. Автотесты используют WebKit с профилем iPhone 16 Pro Max и Edge. Фоновая синхронизация после закрытия приложения не обещается. Расширения P2 исходного плана (замеры тела, носимые устройства, многопользовательский режим, внешние адаптеры) не входят в этот личный релиз.
